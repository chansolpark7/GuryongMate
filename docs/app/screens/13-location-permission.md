# 13 Location Permission — 위치 권한 안내·거부 (P1)

Figma: 화면 `73:1969` · Spec `72:622` · 거부 상태 `14-S1` `73:7222`

## 목적
OS 권한 창 전에 "왜 위치가 필요한지"를 말하고, 거부해도 여행은 계속된다는 것을 알린다.

## 진입
11 [여행 시작] 때 When-in-Use 권한이 없을 때. **데모 위치 모드가 켜져 있으면 건너뛴다** (33).

## 레이아웃
흰 배경 · 닫기 · 일러스트(120 원 #EAF0FF + pin 36) · 제목 24 "위치를 켜면 현장에서 함께해요" · 부제 15 "앱을 쓰는 동안에만 위치를 사용해요" · 3행(아이콘 박스 40 r12 + 제목 15 Bold + 설명 13): 도착 알림과 현장 해설 / 늦어질 때 먼저 대안 제안 / 위험 구역 접근 경고 · 개인정보 12 "마지막 위치만 저장하고 이동 기록은 남기지 않아요. 백그라운드 위치는 쓰지 않아요." · [위치 허용] Primary 52 · [위치 없이 계속] 텍스트.

## 동작
| 동작 | 다음 |
|---|---|
| 위치 허용 | OS 권한 요청 → 허용이면 start 계속 → 14 |
| OS 에서 거부 / 위치 없이 계속 | start 는 그대로 진행 → 14-S1 (Amber 배너 "위치가 꺼져 있어요 · 도착 해설·위험 구역 알림이 동작하지 않아요 [켜기]") |
| 배너 [켜기] | 권한 다시 요청, 영구 거부면 OS 설정 열기 |

## 위치 전송 (권한이 있을 때, trip §2.2)
- 화면이 켜진 동안: 30m 이상 움직였거나 30~60초마다 `POST /trip/plans/{id}/location {lat, lng, accuracy, recorded_at, source:"app"}`.
- 끊겼다가 연결되면 모아 둔 점을 `{"points":[…]}`(최대 100, 오래된 순)로.
- 409 `trip_not_active` 면 전송을 멈추고 state 를 다시 읽는다(자동 종료됐을 수 있음).
- 거부 상태에서도 시간 경과로 생기는 `delay` 와 `safety_raised` 는 온다 (서버 틱).
