# demo_script — 데모 4장면 대본 (초안)

> 화면 ID 는 [docs/app/README.md](../app/README.md) §5, 흐름은 [docs/app/flows.md](../app/flows.md) F1~F7, 데모 데이터는 app/README.md §6.1.
> 대본의 시각·문구는 **녹화 fixture(`app/test/fixtures/`, 각본 LLM) 값**이다. 실제 LLM(Claude Haiku 5.5)으로 하면 답변 문장과 몇 분 단위 시각은 달라질 수 있다 — 숫자를 외우지 말고 화면을 읽는다.
> 수치 출처는 [facts.md](facts.md). 시간 목표 합계 **4분 30초** ([outline.md](outline.md) 슬라이드 4~7).

역할: **발표자**(말하며 앱 조작, 화면 미러링) · **조작자**(노트북 터미널에서 CLI 로 위치·가상 시각·가상 상황을 넣음). 발표장은 구룡포가 아니므로 위치는 서버에 넣고 앱은 **데모 위치 모드**로 그린다 (trip/README.md §2.2, 화면 33).

## 0. 준비 (발표 전)

### 0.1 서버 (데모 스택)
```bash
# backend/.env
AGENT_PROVIDER=claude            # 운영 기본 Haiku 5.5. 키·네트워크가 안 되면 scripted (§0.4)
SAFETY_SOURCE=mock               # 가상 상황·시각 (PUT /safety/sim) — 장면 ①~④ 공통
AUTH_REQUIRED=false              # "안전 점검 지금 실행"(POST /planner/safety/scan)이 개발 모드에서만 열림. 아니면 주기 점검(60초)을 기다린다
docker compose up -d --build
curl http://127.0.0.1:8000/health
```
- 앱 33 Settings → [연결 확인]: `agent: claude:claude-haiku-5-5 · safety: 가상 상황` 이 보여야 한다 (`GET /agent/info`, `GET /safety/sim`).
- 조작자 터미널: `export GURYONG_API_URL=http://127.0.0.1:8000` 후 `python scripts/planner/cli.py login <데모 계정>` — **앱과 같은 계정**으로 로그인해 둔다 (planner/README.md §11).

### 0.2 실제 데이터 스택 (장면 ④-0 용)
- 두 번째 worktree 에서 `SAFETY_SOURCE` 를 비우고(실제) `DT_SERVICE_KEY`·`DATA_GO_KR_SERVICE_KEY` 를 넣어 다른 포트(`.env` 의 `API_PORT`)로 띄운다 (COLLABORATION.md §5 "worktree 동시 실행").
- 확인: `GURYONG_API_URL=http://127.0.0.1:<실제 포트> python scripts/planner/cli.py status` 에 센서 10대 실측·방파제 CCTV 집계·특보·12시간 예보 신호가 나오는지.
- **메모리 주의**: 전체 스택 하나가 약 1.8GB, Docker Desktop 한도 약 3.8GB (COLLABORATION.md §5). 두 스택이 안 뜨면 발표 직전에 실제 데이터 화면을 **캡처해 두고 캡처 시각과 함께** 보여준다.

### 0.3 데모 계획과 가이드 노트
- 장면 ① 은 발표 중에 **새로 만든다** (계획 모드, 가상 시각 `2026-10-09 10:00`, `calm` — fixture 녹화와 같은 조건).
- 장면 ②~④ 는 데모 데이터와 같은 계획 "엄마랑 구룡포"(app/README.md §6.1)를 **미리 만들어 둔다** — 실제 LLM 이 장면 ① 에서 만든 일정은 매번 조금 다를 수 있어서다. 발표에서는 "방금 만든 것과 같은 일정"이라고 말한다.
  - CLI: `new "엄마랑 구룡포" --start 2026-10-10 --from 12:30 --to 18:00` → `add` 5곳 (구룡포 일본인 가옥거리 `kto-1909659` 60분, 구룡포항 `kto-2610501` 50분, 구룡포과메기문화관 `kto-2660046` 60분, 구룡포 북방파제 `poi-gr-breakwater-north` 40분, 카페파도 `kto-2834344` 45분 `--mode car`) → `rule <id> end_before time=18:00` → `show <id>` 로 17:38 종료 확인.
  - 그 계획의 Agent 세션을 하나 만들어 둔다 (앱에서 AI 시트를 한 번 열기). 선제 턴이 이 세션으로 온다.
- 가이드 노트: `guide-prepare <id> --wait` (또는 앱 32) 로 5곳 모두 `ready` 확인 (Haiku 5.5 장소당 약 20초).
- 가상 시각을 장면 ② 직전 값으로: `sim scenario calm`, `sim now 2026-10-10T12:20`.

### 0.4 백업 (실패 대비, 위에서부터 차례로)
| 실패 | 대신 |
|---|---|
| Claude API 오류·크레딧 (`llm_unavailable`·`llm_quota`) | `AGENT_PROVIDER=scripted` 로 agent 만 다시 띄움 — 각본 LLM 은 장면 ①~④ 데모 문장에 맞춰져 있고 도구·카드·검토 관문은 진짜로 돈다 (agent/README.md §7.2) |
| 수동 조작 순서가 꼬임 | 검증된 재생 파일: `trip replay new scene2_arrival --speed 0` / `scene3_delay --speed 0` / `scene4_safety --speed 60` (trip/README.md §8). 새 계획이 생기므로 앱에서 그 계획을 연다 |
| 앱 동행 화면이 발표 빌드에 없음 | 앱은 계획 모드(①)까지, 장면 ②~④ 는 CLI 화면(`trip events <id> --follow`, `chat <id>`)과 Figma 화면(Page 1 화면 11~36)을 나란히 |
| 네트워크 전체 | 녹화 fixture 로 도는 앱 + 미리 녹화한 화면 영상 |

> 현재 상태 (2026-10-10): `dev` 의 앱은 계획 모드(01~10)이고, 개정 계획 모드·안전 화면 25~28·설정 33 은 `feat/app-l1`(미머지), 동행 화면(11·14~23)은 명세 단계다. 발표 빌드에 무엇이 들어가는지 확인하고 이 표를 고친다.
